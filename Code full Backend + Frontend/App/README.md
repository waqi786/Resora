**Resora** is a high-performance desktop research assistant designed for scholars, PhD students, and research teams. It streamlines the literature review process using semantic search, AI-driven analysis, and automated screening.

---

##  Technical Overview

Resora is built on a decoupled architecture where the **PyQt5 Frontend** interacts with a modular **NLP Backend** and a robust **SQLite Persistence Layer**. It is designed to run efficiently on CPU-only environments while still providing state-of-the-art transformer-based summaries and analysis.

### Core Technical Pillars:
1.  **Vector Search**: Inner-product similarity search using **FAISS** on 384-dimensional embeddings generated by `all-MiniLM-L6-v2`.
2.  **Neural Synthesis**: Sequence-to-sequence summarization using the `BART-large-cnn` architecture.
3.  **Relational Persistence**: 15+ relational tables in SQLite for deep workspace management.
4.  **Resilient Architecture**: Built-in fallbacks (TF-IDF search & Heuristic summarization) ensure functionality even if high-end models fail to load.

---

## 🏗️ System Architecture

### 1. ML Backend (`ml_backend.py`)
*   **Search Engine**: Implements `faiss.read_index` for O(log N) retrieval. It maps user queries into the same vector space as the ArXiv embeddings.
*   **Summarization**: Implements `transformers.BartForConditionalGeneration`. Max/Min token length is user-configurable via the UI to control summary density.
*   **Heuristics**: Includes a custom keyword-density algorithm for detecting methodology and research types, used both as an extraction tool and a screening fallback.

### 2. Database Schema (`database.py`)
The system manages data via 15 normalized tables:
*   `users`: Manages subscription tiers, hashed passwords, and research credits.
*   `projects` & `project_papers`: A many-to-many relationship allowing users to organize literature into distinct research projects.
*   `screening_sessions`: Stores threshold-based Inclusion/Exclusion results and audit logs.
*   `payments`: Tracks Stripe invoice history and transaction statuses.
*   `ai_chats`: Persists conversational history for the AI Assistant.

### 3. UI Framework (`main.py`)
*   **Custom Theming**: A bespoke Slate-Indigo SaaS theme implemented via **QSS** (Qt Style Sheets).
*   **Multi-Threading**: All heavy I/O and ML inference tasks are offloaded to `QThread` and `QWorker` objects to prevent the main GUI loop from hanging.
*   **Responsive Layout**: Uses `QSplitter` and `QScrollArea` to ensure usability on screens from 13" laptops to 4K monitors.

## ⚡ Feature Deep-Dive

### 🔍 Smart Semantic Search
Unlike standard keyword search, Resora understands conceptual relationships. Searching for *"Attention is all you need"* will prioritize papers on Transformers even if the titles differ.
*   **Thresholding**: Search scores are normalized (0.0 to 1.0) to indicate relevance.
*   **Filtering**: Real-time filtering by Year and specific ArXiv categories (e.g., cs.AI, stat.ML).

### 📊 PRISMA 2020 Automation
One of the most unique features of Resora is its ability to generate high-fidelity PRISMA diagrams.
*   **Logic**: It tracks papers through the Identification, Screening, Eligibility, and Inclusion phases.
*   **Rendering**: Uses `matplotlib` with `FancyBboxPatch` to create publication-quality visuals.

### 💳 Billing & Security
*   **Stripe**: Environment variable based secret key integration for secure payment flows.
*   **Promo Engine**: Dynamic credit/plan upgrades via encoded keys (e.g., `RESORA2026`).
*   **API Access**: Secure 40-character hex key generation for external integrations.

## 🚀 Execution & Performance

### Initialization
On the first run, the app:
1.  Seeds the SQLite database with default admin credentials.
2.  Loads the 250MB FAISS index into memory (RAM usage: ~1.2GB).
3.  Downloads the BART model from Hugging Face (if not locally cached).

### Start the application:
```bash
python main.py
```

| :--- | :--- |
| `WinError 1114` | Run `setup_fix.bat`. This is a common PyTorch DLL conflict on Windows. |

## Architecture and data flow

### Backend

- `ml_backend.py`
  - Loads FAISS index from `data/arxiv_faiss.index`
  - Loads metadata from `data/arxiv_metadata.csv`
  - Loads embeddings from `data/arxiv_embeddings.npy`
  - Uses `sentence-transformers` (`all-MiniLM-L6-v2`) for semantic queries
  - Falls back to TF-IDF search when semantic models are unavailable
  - Provides summarization and paper analysis APIs

- `database.py`
  - Uses SQLite with WAL journaling and foreign key support
  - Stores users, sessions, bookmarks, summaries, screenings, payments, notifications, tasks, projects, and audit logs
  - Seeds the admin user automatically on first run

### Frontend

- `main.py`
  - Builds the entire PyQt5 desktop interface
  - Implements navigation, page widgets, user forms, search, analysis, summaries, and exports
  - Handles plan-based feature access and user credit management
  - Creates a modern dark SaaS-style UI with cards, buttons, tabs, and responsive panels

## Troubleshooting

### Common errors

- `ModuleNotFoundError: No module named 'PyQt5'`
  - `pip install PyQt5`

- `ModuleNotFoundError: No module named 'faiss'`
  - `pip install faiss-cpu`

- `ImportError` or `WinError 1114` from PyTorch
  - Reinstall CPU-only PyTorch:

```powershell
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu
```

- App cannot find data files
  - Confirm `data/arxiv_faiss.index`, `data/arxiv_metadata.csv`, and `data/arxiv_embeddings.npy` exist

### Performance notes

- The first model load may take several seconds to download or initialize
- Semantic search performs best with the locally cached `all-MiniLM-L6-v2` model
- If the summarizer fails to load, the app uses a fallback extractive summarization method
